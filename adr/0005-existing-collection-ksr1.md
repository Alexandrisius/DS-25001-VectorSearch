# ADR-0005 — Что делать с существующей коллекцией `ksr_1`

**Дата:** 2026-06-16
**Статус:** ✅ Принято (рекомендация пользователю)
**Связано с:** [ADR-0001](0001-fix-diff-false-positives.md)

## Контекст

Коллекция `ksr_1` — единственная продакшен-коллекция, **144 680 записей** в Qdrant. Импортирована ДО фиксов, поэтому содержит **stale-данные**, на которых новые фиксы ещё не отразились.

### Проверка реальных данных

Скрипт `inspect_ksr1.py` (запущен против прода) показал:

| Что | Сколько | Где |
|---|---|---|
| Всего точек в `ksr_1` | 144 680 | Qdrant |
| С `path_depth=2` (иерархия из 2 уровней) | ~99.99% | Qdrant |
| С «ёлочками» в `description` | **122+** (на выборке 50 000) | Qdrant |
| Где `description == full_description` | **100%** (для всех проверенных) | Qdrant |

### Что это значит

1. **Bug #2 (кавычки) АКТИВЕН для `ksr_1`** — 122+ записей с «ёлочками» дают ложные "изменения" в diff. Это и есть те самые 255 у пользователя.
2. **Bug #1 (description=full_description) НЕ активен для `ksr_1`** — в этой коллекции `description` и `full_description` равны по построению (Excel: описание в одной колонке, иерархия в отдельных; `generate_path_levels` корректно это обрабатывает). Фикс Bug #1 — **защита на будущее** для других коллекций / форматов Excel.

### Коллекция не сломана

- Embeddings валидны, поиск работает.
- BM25 индекс работает.
- `materials_count` корректный.
- Diff продолжает показывать ~255 модификаций **до первого re-import** — это **только косметический дефект** UI, не влияет на функциональность.

## Решение (рекомендация пользователю)

### Вариант 1 — Полный re-import (рекомендуется)

```bash
# В UI: Админка → Импорт данных → Excel → загрузить тот же файл
# → применить маппинг → "Загрузить всё" (не "Сравнить")
```

**Что произойдёт:**
1. `ImportService.import_records` прогонит 144 680 записей через новый пайплайн.
2. На каждой `description` будет применён `strip_symmetric_quotes` — «ёлочки» снимутся.
3. Qdrant обновится через `qdrant.upsert` (идемпотентно по `deterministic_uuid(code)`).
4. После re-import: diff с тем же Excel → **0/0/0/0**.

**Стоимость:**
- Время: ~10-15 минут (зависит от провайдера эмбеддингов).
- Стоимость OpenRouter: пересчёт 144 680 embeddings ≈ пара центов.
- Желательно делать в низкий трафик.

**Плюсы:** чистые данные, diff=0, никаких сюрпризов.
**Минусы:** пересоздание embeddings (можно ли дешевле — см. вариант 2).

### Вариант 2 — Точечный reindex (если Excel потерян)

Скрипт `C:\tmp\reindex_quoted_only.py` (написать при необходимости):
- SELECT из Qdrant всех записей, где `description` содержит `«` или `»`
- Для каждой: пересохранить через `MaterialService.upsert` (с новым `description` без кавычек)
- Сгенерировать только N эмбеддингов (а не 144 680)

**Плюсы:** в 1000× быстрее и дешевле.
**Минусы:** нужен новый код, не покрыт тестами.

### Вариант 3 — Ничего не делать

Оставить как есть. Фиксы в коде уже работают — **новые импорты** уже сохраняются правильно. Старые 122 записи так и будут с «ёлочками», но это:
- Не влияет на поиск (эмбеддинги считаются по `context_description`, который формируется ДО сохранения и одинаков что с кавычками, что без).
- Не влияет на BM25.
- Просто показывает ложные "изменения" в diff, пока пользователь не сделает re-import.

## Последствия

- **Не рекомендуется удалять коллекцию** — это единственная коллекция, потеря данных критична.
- Любой из вариантов 1-3 безопасен. Вариант 1 — самый чистый.
- Если пользователь выберет Вариант 1, после re-import дополнительных действий не требуется.
