## ✨ Возможности

- **Two-Stage Retrieval**: Двухэтапный поиск (векторный + reranking)
- **Локальные модели**: Qwen3-Embedding-4B + BGE-Reranker-v2-M3
- **Qdrant**: Векторная БД с косинусной метрикой
- **Модуль Каталог**: Интерактивный сайдбар с иерархией категорий и фильтрацией
- **Иерархический поиск**: Фильтрация результатов по категориям (одиночная и множественная)
- **Административная панель**: Управление коллекциями через веб-интерфейс
- **Hot Reload**: Обновление данных без перезапуска сервера
- **Аналитика**: Сбор обратной связи (копирование, дизлайки)
- **Тёмная тема**: Современный UI с поддержкой тёмной/светлой темы

## 🚀 Установка и запуск

### Требования

- Python 3.10+
- CUDA-compatible GPU (рекомендуется 8GB+ VRAM)
- RAM: минимум 16GB

### 1. Установка зависимостей

```bash
pip install -r docs/requirements.txt
```

### 2. Настройка путей к моделям

Отредактируйте файл `src/config.py`:

```python
# Укажите пути к вашим моделям
QWEN_MODEL_PATH = r"D:\hf_cache\Qwen3-Embedding-4B"
RERANKER_PATH = r"D:\hf_cache\bge-reranker-v2-m3"
```

### 3. Запуск сервера

```bash
python src/server.py
```

Сервер будет доступен по адресу: `http://localhost:8000`

## ⚙️ Конфигурация

Вся конфигурация вынесена в `src/config.py`:

| Параметр | Описание | Значение по умолчанию |
|----------|----------|----------------------|
| `PROJECT_ROOT` | Корневая директория проекта | Автоопределение |
| `QWEN_MODEL_PATH` | Путь к модели эмбеддингов | `D:\hf_cache\Qwen3-Embedding-4B` |
| `RERANKER_PATH` | Путь к модели реранкера | `D:\hf_cache\bge-reranker-v2-m3` |
| `MAX_TOKEN_LENGTH` | Максимальная длина токенов для модели | 1024 |
| `EMBEDDING_BATCH_SIZE` | Размер батча для генерации эмбеддингов | 32 |
| `UPLOAD_BATCH_SIZE` | Размер батча для загрузки в Qdrant | 100 |
| `DEFAULT_TOP_K_QDRANT` | Количество кандидатов из Qdrant (Stage 1) | 500 |
| `DEFAULT_MAX_FOR_RERANK` | Количество кандидатов для реранкинга (Stage 2) | 100 |
| `DEFAULT_MAX_RESULTS` | Максимальное количество результатов в ответе | 100 |
| `EMBEDDING_CACHE_SIZE` | Размер LRU-кэша эмбеддингов | 15000 |
| `DEFAULT_COSINE_THRESHOLD` | Порог косинусного сходства | 0.45 |
| `DEFAULT_RERANK_THRESHOLD` | Порог реранкера | 0.6 |

### Конфигурация коллекций

Файл `src/vector_databases.json`:

```json
{
  "ksr_main": {
    "description": "База КСР 'ЕвроХим'",
    "columns": {"code": "code", "description": "description"},
    "thresholds": {"cosine": 0.45, "rerank": 0.6},
    "last_updated": "29.11.2025",
    "visible": true,
    "locked": true
  }
}
```

**Параметры коллекции:**
- `description` — описание коллекции
- `columns` — маппинг колонок (code, description)
- `thresholds` — пороги фильтрации (cosine, rerank)
- `visible` — видимость в интерфейсе поиска
- `locked` — защита от случайного удаления

### Поиск

```bash
# Базовый запрос
curl -X POST http://localhost:8000/match \
  -H "Content-Type: application/json" \
  -d '{"text": "трубы стальные", "database": "ksr_main"}'

# С фильтрацией по категории (одиночный фильтр)
curl -X POST http://localhost:8000/match \
  -H "Content-Type: application/json" \
  -d '{
    "text": "трубы стальные",
    "database": "ksr_main",
    "filter_path": "Арматура → Трубы",
    "filter_level": 2
  }'

# С множественной фильтрацией (OR логика)
curl -X POST http://localhost:8000/match \
  -H "Content-Type: application/json" \
  -d '{
    "text": "трубы стальные",
    "database": "ksr_main",
    "filter_paths": [
      {"path": "Арматура → Трубы", "level": 2},
      {"path": "Материалы → Металл", "level": 2}
    ]
  }'
```

**Ответ:**
```json
{
  "query": "трубы стальные",
  "database": "ksr_main",
  "candidates": [
    {
      "rank": 1,
      "code": "01.01.001",
      "description": "Трубы стальные бесшовные...",
      "reranker_score": 0.8542,
      "cosine_similarity": 0.7823
    }
  ],
  "processing_time": 0.234,
  "status": "success"
}
```

**Параметры запроса:**
- `text` (обязательный) — текст запроса для поиска
- `database` (опционально) — имя коллекции (по умолчанию активная)
- `filter_path` (опционально) — путь категории для одиночной фильтрации
- `filter_level` (опционально) — уровень иерархии для фильтрации
- `filter_paths` (опционально) — массив путей для множественной фильтрации (OR логика)

## 📂 Модуль Каталог

Интерактивный сайдбар для просмотра иерархии коллекций и фильтрации результатов поиска.

### Основные возможности

1. **Иерархическое дерево категорий**
   - Ленивая загрузка (загружаются только видимые категории)
   - Раскрытие/сворачивание узлов дерева
   - Отображение количества записей в каждой категории
   - Визуальная индикация папок и листьев

2. **Поиск по каталогу**
   - Семантический поиск категорий через векторный поиск
   - Автодополнение и подсказки
   - Быстрый переход к найденным категориям

3. **Фильтрация результатов**
   - **Одиночный выбор**: Клик по категории применяет фильтр
   - **Множественный выбор**: Ctrl+клик (или Cmd+клик на Mac) для выбора нескольких категорий
   - Визуальная индикация выбранных категорий
   - Сброс фильтров одной кнопкой

4. **Настройка интерфейса**
   - Изменение ширины сайдбара (перетаскивание границы)
   - Сворачивание/разворачивание каталога
   - Sticky header текущей категории при прокрутке
   - Сохранение состояния в localStorage

5. **Дополнительные функции**
   - Копирование кодов прямо из дерева категорий
   - Статистика: общее количество категорий и записей
   - Кнопка "Свернуть все" для быстрой навигации
   - Индикатор активного фильтра (виден при свёрнутом сайдбаре)

### Использование

**Базовые действия:**
- **Клик по категории** — раскрывает/сворачивает узел дерева
- **Ctrl+клик** — добавляет/убирает категорию из фильтра (множественный выбор)
- **Клик на иконку копирования** — копирует код категории в буфер обмена
- **Перетаскивание границы** — изменяет ширину сайдбара

**Поиск по каталогу:**
1. Введите текст в поле "Поиск категорий..."
2. Система выполнит семантический поиск по категориям
3. Выберите нужную категорию из результатов

**Фильтрация результатов:**
1. Выберите одну или несколько категорий (Ctrl+клик)
2. Выполните поиск — результаты будут отфильтрованы по выбранным категориям
3. Для сброса фильтра нажмите кнопку "Сбросить" в подсказке

### Технические детали

- **Ленивая загрузка**: Категории загружаются только при раскрытии узла, что обеспечивает быструю работу даже с большими иерархиями
- **Кэширование**: Результаты иерархии кэшируются на сервере (TTL 5 минут)
- **Оптимизация**: Используется прямой запрос к Qdrant без построения полного дерева для ленивой загрузки
- **Структура данных**: Иерархия строится на основе полей `path_level_N` в метаданных Qdrant

## 📊 ETL Пайплайны

### 1. Очистка данных

```bash
python scripts/pipelines/01_clean_raw.py
```

Преобразует Excel → CSV с очисткой и формированием `full_path` (иерархический путь с разделителем "→").

**Вход:** `data/01_raw/*.xlsx`  
**Выход:** `data/02_interim/KSR_clean.csv`

### 2. Создание коллекции

```bash
python scripts/pipelines/02_create_qdrant_collection.py \
  --input "data/02_interim/KSR_clean.csv" \
  --collection "ksr_main" \
  --recreate
```

**Параметры:**
- `--input` — путь к CSV файлу
- `--collection` — имя коллекции в Qdrant
- `--recreate` — пересоздать коллекцию если существует
- `--no-config` — не добавлять в `vector_databases.json` (для тестовых коллекций)

**Процесс:**
1. Загрузка данных из CSV
2. Генерация эмбеддингов батчами
3. Создание коллекции через API сервера
4. Загрузка векторов и метаданных
5. Автоматическое обновление конфигурации

### 3. Инкрементальное обновление

```bash
python scripts/pipelines/03_update_qdrant_collection.py \
  --input "data/02_interim/KSR_clean.csv" \
  --collection "ksr_main"
```

**Флаги:**
- `--dry-run` — предпросмотр изменений без применения
- `--no-delete` — не удалять отсутствующие записи

**Анализ изменений:**
- Определяет новые записи (добавление)
- Определяет изменённые записи (обновление)
- Определяет удалённые записи (удаление)

### 4. Миграция иерархических полей

```bash
# Миграция всех коллекций
python scripts/service/migrate_path_levels.py

# Миграция конкретной коллекции
python scripts/service/migrate_path_levels.py --collection ksr_main

# Сухой прогон (проверка без изменений)
python scripts/service/migrate_path_levels.py --dry-run
```

Добавляет поля `path_level_1`, `path_level_2`, ..., `path_depth` в существующие записи Qdrant для поддержки фильтрации по категориям.

**Параметры:**
- `--collection` — имя коллекции (по умолчанию — все коллекции)
- `--dry-run` — режим проверки без изменений
- `--separator` — разделитель иерархии (по умолчанию "→")

### 5. Вспомогательные скрипты

**Конвертация данных:**
```bash
python scripts/service/convert_excel_to_jsonl.py
```

**Валидация:**

- `QdrantVectorDatabaseManager` — основной менеджер БД и моделей
  - Управление коллекциями
  - Генерация эмбеддингов (Qwen3-Embedding-4B)
  - Поиск в Qdrant с фильтрацией
  - Кэширование эмбеддингов
- `BackgroundJobManager` — менеджер фоновых задач (импорт данных)
- `HierarchyService` — сервис для работы с иерархией категорий
  - Построение дерева категорий
  - Ленивая загрузка дочерних элементов
  - Кэширование результатов (TTL 5 минут)
  - Семантический поиск по категориям

### Структура данных

**Метаданные записи в Qdrant:**
```json
{
  "code": "01.01.001",
  "description": "Трубы стальные бесшовные...",
  "full_path": "Арматура → Трубы → Стальные",
  "path_level_1": "Арматура",
  "path_level_2": "Арматура → Трубы",
  "path_level_3": "Арматура → Трубы → Стальные",
  "path_depth": 3
}
```

**Поля иерархии:**
- `full_path` — полный иерархический путь (разделитель "→")
- `path_level_N` — путь до уровня N (для фильтрации)
- `path_depth` — глубина вложенности категории

### Логирование

- Серверные логи выводятся в консоль (INFO level)
- Аналитика сохраняется в `data/04_feedback/`:
  - `positive.jsonl` — события копирования
  - `negative.jsonl` — события дизлайков

### Иерархия категорий

Система поддерживает многоуровневую иерархию категорий на основе поля `description` с разделителем "→".

**Пример:**
```
Арматура → Трубы → Стальные → Бесшовные
```

**Автоматическая генерация полей:**
- `path_level_1`: "Арматура"
- `path_level_2`: "Арматура → Трубы"
- `path_level_3`: "Арматура → Трубы → Стальные"
- `path_level_4`: "Арматура → Трубы → Стальные → Бесшовные"
- `path_depth`: 4

Эти поля используются для:
- Фильтрации результатов поиска по категориям
- Построения дерева каталога
- Навигации по иерархии

### Формат данных CSV

Ожидаемые колонки в `data/02_interim/KSR_clean.csv`:
- `code` — код ресурса (уникальный идентификатор)
- `description` — описание с иерархией (разделитель "→")
- `full_path` — полный путь (генерируется автоматически)
