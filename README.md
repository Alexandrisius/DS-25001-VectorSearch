## 1. Архитектура Системы

Система реализует паттерн **Two-Stage Retrieval (Hybrid Search)** для обеспечения максимальной релевантности поиска по нормативной документации (КСР).

### High-Level Data Flow
1.  **Ingestion**: Сырые данные (Excel) очищаются и преобразуются в текстовые строки (`full_path`).
2.  **Embedding**: Тексты векторизуются моделью `Qwen-Embedding-4B` (размерность зависит от модели, FP16).
3.  **Indexing**: Векторы сохраняются в `Qdrant` (Local Mode, SQLite backend) с метаданными.
4.  **Retrieval (Stage 1)**: По запросу пользователя ищутся топ-1500 кандидатов через ANN (Approximate Nearest Neighbors) по косинусному сходству.
5.  **Reranking (Stage 2)**: Топ-200 кандидатов переранжируются Cross-Encoder моделью `BGE-M3` (Score-based sorting).
6.  **Presentation**: Результаты отдаются на Frontend через REST API.

## 3. Компонент: Backend (`src/server.py`)

Сервер построен на фреймворке **FastAPI**. Он обеспечивает асинхронную обработку запросов, управление состоянием моделей и взаимодействие с векторной БД.

### Основные классы

#### 1. `EmbeddingCache`
In-memory LRU-кэш для эмбеддингов запросов. Позволяет избегать повторной генерации векторов для частых запросов.
*   **Атрибуты**: `cache` (dict), `max_size` (15000), `lock` (asyncio.Lock).
*   **Методы**:
    *   `get(text)`: Возвращает кэшированный вектор. Ключ нормализуется (`lower().strip()`).
    *   `set(text, embedding)`: Сохраняет вектор, удаляя старые записи при переполнении.

#### 2. `QdrantVectorDatabaseManager`
Центральный класс для работы с данными.
*   **Инициализация**: Загружает модели `Qwen` (локально) и подключается к Qdrant.
*   **Управление конфигом**: Метод `load_configuration()` читает `vector_databases.json`.
*   **Методы поиска**:
    *   `search_vectors(...)`: Асинхронный поиск в Qdrant через `ThreadPoolExecutor` (для обхода GIL при работе с клиентом Qdrant).
    *   `get_embedding_cached(...)`: Получение вектора запроса (через кэш или генерацию).
*   **Методы CRUD**: `update_record`, `delete_record`, `get_record_by_code`.

### Ключевые методы логики

#### `_get_embedding_sync(text)`
Генерирует эмбеддинг с помощью модели `AutoModel` (HuggingFace Transformers).
*   **Вход**: Текст запроса.
*   **Процесс**: Токенизация (max 1024 токенов) -> Inference (CUDA/CPU) -> Last Token Pooling (специфика Qwen) -> L2 Normalization.
*   **Выход**: NumPy array (`float32`).

#### `match_ksr(request)` (API Endpoint Logic)
Основной пайплайн поиска:
1.  Получение эмбеддинга запроса.
2.  `search_similar`: Поиск кандидатов в Qdrant (фильтр по `cosine_threshold`).
3.  Если кандидатов нет -> возвращает пустой список.
4.  Если кандидаты есть -> берет топ-200 для Reranking.
5.  `reranker.predict(...)`: Вычисление скоров релевантности пар (Запрос, Кандидат).
6.  Фильтрация по `rerank_threshold` (0.6).
7.  **Fallback**: Если после фильтрации пусто, возвращает топ-20 лучших по скору (даже если < 0.6), логируя warning.

### API Endpoints

| Метод | Путь | Описание | Payload |
|-------|------|----------|---------|
| `GET` | `/` | Возвращает HTML интерфейс | - |
| `POST` | `/match` | Поиск похожих записей | `{"text": "...", "database": "..."}` |
| `GET` | `/databases` | Список доступных баз | - |

| `POST` | `/feedback/copy` | Логирование копирования (Analytics) | JSON Event |

## 4. Компонент: ETL Pipelines (`scripts/`)

Скрипты для подготовки данных ("Extract, Transform, Load").

### `01_clean_raw.py`
Отвечает за очистку "грязных" Excel-файлов.
*   **Библиотеки**: `pandas`, `openpyxl`.
*   **Логика**:
    *   Читает Excel с сохранением типов строк (чтобы не потерять ведущие нули в кодах).
    *   `clean_ksr_text`: Удаляет префиксы "Раздел X", "Группа Y" через RegEx.
    *   Формирует `full_path`: конкатенация иерархии через " → ".
    *   Валидирует данные (проверка на пустые пути).
*   **Результат**: CSV файл с разделителем `;`.

### `02_create_qdrant_collection.py`
Скрипт "полного цикла" для создания поискового индекса.
*   **Аргументы CLI**: `--input`, `--collection`, `--recreate`, `--server-url`.
*   **Класс `EmbeddingGenerator`**:
    *   Обертка над моделью Qwen.
    *   Реализует батчевую генерацию (`generate_all`) с прогресс-баром `tqdm`.
    *   Управляет памятью GPU (`torch.cuda.empty_cache`).
*   **Взаимодействие с сервером**:
    *   Не пишет в БД напрямую (файлы заняты сервером).
    *   Использует API сервера: `POST /create_collection` -> `POST /upload_batch`.
    *   В конце обновляет локальный `vector_databases.json` и дергает `POST /reload_config`.

### `03_update_qdrant_collection.py`
Скрипт "умного" инкрементального обновления (Hot Update).
*   **Назначение**: Обновление данных без простоя сервиса и полной перегенерации базы.
*   **Логика**:
    1.  Сравнивает новые данные (CSV) с текущими данными в Qdrant (через API).
    2.  Выявляет изменения (новые, измененные, удаленные записи).
    3.  Применяет изменения точечно через API (`upsert`, `delete`).
    4.  **Timestamp**: После успешного обновления проставляет текущую дату (`last_updated`) в конфиг и перезагружает сервер.

## 5. Компонент: Frontend (`web/`)

Легковесный SPA (Single Page Application) без использования фреймворков (No React/Vue), только нативный JS.

### Структура UI (`index.html`)
*   **Header**: Выбор темы (Dark/Light), логотип.
*   **Search Area**: Крупное поле ввода, кнопка поиска, выбор базы данных (Custom Dropdown).
    *   Карточки баз данных отображают дату последнего обновления (dd.mm.yyyy).
*   **Results Table**: Таблица с колонками:
    *   Ранг (Rank)
    *   Код КСР (с кнопкой копирования)
    *   Описание
    *   Действия (Дизлайк)
    *   Метрики (Progress bars для Rerank/Cosine score).

### Стили (`styles.css`)
*   **CSS Variables**: Активное использование переменных (`--primary`, `--bg-dark`, `--text-main`) для темизации.
*   **Dark Mode**: Реализован через атрибут `data-theme="dark"` на теге `<html>`.
*   **Adaptive**: Flexbox верстка, резиновые поля.
*   **Анимации**: Спиннеры загрузки, плавные переходы цветов (`transition: all 0.3s`).

### Логика (`app.js`)
*   **Инициализация**: Загрузка списка баз (`/databases`), восстановление темы из `localStorage`.
*   **Поиск**:
    *   `performSearch()`: Асинхронный fetch-запрос.
    *   Блокировка кнопки во время запроса, показ спиннера.
    *   Обработка ошибок сети.
*   **Отрисовка**: Генерация HTML строк для таблицы результатов (`displayResults`).
*   **Аналитика**:
    *   Делегирование событий (Event Delegation) для кнопок в таблице.
    *   Отправка `POST /feedback/copy` при копировании кода.
    *   Отправка `POST /feedback/dislike` при нажатии на палец вниз.

## 6. Конфигурация и Данные

### Конфигурация БД (`src/vector_databases.json`)
Файл управляет метаданными коллекций. Изменения в этом файле подхватываются сервером на лету (через reload endpoint).
```json
{
  "ksr_main": {
    "description": "Основная база КСР",
    "columns": { "code": "code", "description": "description" },
    "thresholds": {
      "cosine": 0.45,  // Порог для первого этапа (Qdrant)
      "rerank": 0.6    // Порог для второго этапа (BGE)
    },
    "record_count": 121000,
    "dimension": 1024,
    "last_updated": "29.11.2025" // Дата последнего обновления (автоматически)
  }
}
```

### Логирование
*   **Server Logs**: Stdout (консоль) с уровнем INFO. Логируются время выполнения запросов, ошибки, инициализация.
*   **Analytics Logs** (`data/04_feedback/`):
    *   Формат JSONL (JSON Lines).
    *   Содержат запрос, выбранный результат, скоры и timestamp.

## 7. Инструкция по развертыванию

### Требования
*   Python 3.10+
*   CUDA-compatible GPU (рекомендуется 8GB+ VRAM) для быстрой работы. На CPU работать будет, но медленно.
*   RAM: минимум 16GB.

### Установка путей
**Внимание**: Пути к моделям захардкожены в `src/server.py` и требуют правки перед запуском на новой машине:
```python
# src/server.py, lines 50-51
QWEN_MODEL_PATH = r"ПУТЬ_К_ПАПКЕ_С_МОДЕЛЬЮ_QWEN"
RERANKER_PATH = r"ПУТЬ_К_ПАПКЕ_С_МОДЕЛЬЮ_BGE"
```

### Запуск
1.  **Backend**: `python src/server.py`
2.  **Доступ**: Открыть браузер по адресу `http://localhost:8000`.
